Mistake Notes is a student-facing wrong-answer review application. Each student can only read their own records, filter by course, knowledge point, and question keyword, inspect the original answer and historical feedback, and maintain versioned cause notes, review notes, and note images. Wide screens provide a two-column question/note workspace and a draggable in-app floating note window.

## Features

- Session-based authentication with Argon2 password hashes and CSRF-protected writes.
- Strict per-student record ownership checks for details, notes, versions, and images.
- Course, knowledge-point, and keyword filters; the API accepts both `course` and `courseId`.
- Markdown and KaTeX rendering with per-formula fallback instead of replacing the whole question.
- Sanitized historical HTML answers through DOMPurify.
- Current cause/review notes with an explicit save action; empty strings are valid and remain empty after login or container rebuild.
- Named version history with create, view, rename, and restore operations.
- Original note-image upload without recompression, including protected image reads and named-volume persistence.
- Responsive detail layout with a sticky note column on wide screens and a draggable/collapsible floating note window.
- Light and dark themes using shared CSS tokens.

## Tech Stack

- Backend: Python 3.12, FastAPI, SQLAlchemy 2, Pydantic, Uvicorn.
- Database: PostgreSQL 16.
- Frontend: React 18, TypeScript, Vite, Ant Design, Lucide icons.
- Math and text: react-markdown, remark-math, rehype-katex, KaTeX, DOMPurify.
- Tests and automation: pytest, Playwright Core, Node.js acceptance scripts.
- Packaging: Docker Compose, `uv.lock`, and `package-lock.json`.

No runtime CDN is required. Frontend assets and fonts are bundled by Vite into the application image.

## Configuration

Configuration is supplied through environment variables. Never commit real secrets.

| Variable | Purpose | Example |
|---|---|---|
| `DATABASE_URL` | SQLAlchemy database URL used by the app | `postgresql+psycopg://mistake_notes:...@db:5432/mistake_notes` |
| `SESSION_SECRET` | Signs the session cookie; replace the local default outside development | `replace-with-a-long-random-secret` |
| `NOTE_IMAGE_DIR` | Directory used for original uploaded image files | `/app/note_images` |
| `FRONTEND_DIST` | Directory containing the built frontend | `/app/frontend_dist` |
| `APP_ENV` | Enables production cookie behavior when set to `production` | `development` |
| `POSTGRES_DB` | Database name used by Compose | `mistake_notes` |
| `POSTGRES_USER` | Database user used by Compose | `mistake_notes` |
| `POSTGRES_PASSWORD` | Local database password placeholder | `change-me-for-local-development` |

Secrets are read only from the environment or ignored `.env` files. The repository contains placeholder values only.

## Data Persistence

Compose creates two named volumes:

- `mistake_notes_postgres_data` is mounted at `/var/lib/postgresql/data` and stores records, current notes, version history, and image metadata.
- `mistake_notes_note_images` is mounted at `/app/note_images` and stores the original uploaded image files.

Use `docker compose down` to stop containers while preserving both volumes. `docker compose down -v` intentionally removes them for a clean initialization.

## Math And Answer Rendering

- Question text is rendered as Markdown with `remark-math` and `rehype-katex`.
- Formula validation and rendering happen per fragment. If one formula fails, only that fragment shows its original source in a readable error element; the rest of the question and other formulas still render.
- Display formulas can scroll horizontally within their own container rather than forcing the page wider.
- Historical HTML answers are sanitized with DOMPurify. Only a small allowlist of structural tags is retained; scripts, event handlers, styles, iframes, objects, and embedded content are removed.
- `text_latex` answers use the same KaTeX rendering path as questions.

## Testing

Backend tests:

```bash
cd backend
uv sync --frozen
uv run pytest -q
```

Frontend build and browser/API acceptance:

```bash
cd frontend
npm ci
npm run build
node scripts/filter-acceptance.mjs
node scripts/acceptance.mjs
```

Verified scenarios from the current repository:

1. Core workflow: `student_001` logs in, filters for `写出四阶`, opens `wrong_001`, saves a note, clears both fields, saves again, logs out, logs back in, and confirms the fields remain empty. The browser test reports `PASS 核心流程重登确认`; empty values are persisted instead of restoring old content.
2. Isolation: `student_002` opens `student_001`'s `wrong_001`. The page reports `403` and displays `无权访问该记录`; pytest also checks cross-student note and version operations return `403`.
3. Persistence: save a note and upload an image for `student_001`, inspect the versions, run `docker compose down`, then `docker compose up --build -d` without `-v`, and log in again. The note, version history, and image remain available from the named volumes.
4. Filter benchmark: `node scripts/filter-acceptance.mjs` reads the supplied expected cases and reports `PASS expected-filters 16/16`.
5. Full browser suite: `node scripts/acceptance.mjs` covers rendering, note persistence/clearing, version naming and restore, image upload/delete, wide/two-column layout, floating-window viewport clamping, sanitization, error handling, theme switching, and deep-link preservation.

## Known Limitations

- PostgreSQL 16 is the supported database target; other database engines are not validated.
- Uploaded images are stored as original bytes. They are not compressed, resized, or transcoded.
- The automated browser suite is validated against one local Chromium/Chrome environment rather than a browser matrix.
- Records are returned without pagination because the assessment dataset is small.
- The app does not include registration, password recovery, captcha, teacher administration, grade synchronization, or analytics.
- Historical scores and feedback are display-only; the application does not recompute or complete them.
- The Ant Design vendor chunk remains large and produces a Vite chunk-size warning, but it is split from application and KaTeX code.

Mistake Notes is provided for course assessment and demonstration only.
